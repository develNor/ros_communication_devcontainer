# Testing

This project separates copyable examples from verification configs:

- **Examples** teach one idea each. They live in
  `src/rosotacom/resources/examples/` and are copied with
  `rosotacom examples create`.
- **Test-configs** cover combinations. The heartbeat RMW matrix lives in
  `tests/sessions/rmw_matrix` and is generated by
  `tests/sessions/generate_rmw_matrix.py`.

## Test Layers

| Layer | Location | Docker | Network | Runs in |
|---|---|---|---|---|
| host / unit | `tests/unit` | no | none | draft + ready PR |
| contract | `tests/contract` | no | none | ready PR |
| local smoke | `tests/e2e` | yes | one host, isolated bridge | merge gate |
| full local suite | examples + `tests/sessions` | yes | one host, isolated bridge | nightly + manual |
| external OTA | operator deployment | yes | multiple machines | manual promotion gate |

Ready PRs run the non-Docker checks, package validation, and the local smoke
slice. The full local suite also runs nightly. The external OTA gate remains
operator-started before a promotion to `main`.

## Expectations

Per-topic `expect` blocks are behavioral contracts in `session-definition.yaml`.
The status overview consumes them at runtime, and `rosotacom test` asserts the
latest `logs/<peer>/status/status.json` self-report:

```yaml
topics:
  b_to_a:
    - topic: /costmap/costmap
      expect:
        hz: { min: 1, max: 5 }
        latency_ms: { max: 500 }
        loss_pct: { max: 2, stage: com_in }
```

Heartbeat expectations live under `shared.heartbeat.expect`, because heartbeat
topics are generated by the framework rather than listed under `topics:`.
`loss_pct` is exact sequence-gap loss for echo heartbeats and wrapped
`OtaStamped` streams; wrapped streams normally measure it at inbound `com_in`.

`expect.smoke_probe: false` keeps a topic in the generated OTA contract while
excluding it from the synthetic local smoke publisher/probe set and from the
local smoke self-report assertion. Use it only for redundant replay-shape topics
when a nearby representative stream already proves that path in CI.

## Local Check Eligibility

OTA suite membership is the default. There is no `multi_machine` marker.

The only per-session test axis is whether the session can be checked quickly on
one host. `rosotacom.cli.local_check_sessions()` derives that from distinct
per-peer local `domain_id` values:

```yaml
peer_settings:
  a: { domain_id: 46 }
  b: { domain_id: 47 }
```

Configs that cannot be faked locally opt out explicitly:

```yaml
local_check: false
```

That opt-out does not remove the config from the OTA suite. It only removes it
from one-host smoke.

## Local Smoke

`just test-e2e-smoke` runs the local-checkable curated examples. Smoke starts
both peers, verifies crossed topics, checks local-only isolation, and then runs
`rosotacom test` against the session self-report.

The generated RMW matrix is available as an opt-in full local slice:

```bash
ROSOTACOM_RUN_E2E=1 ROSOTACOM_RUN_FULL_E2E=1 \
  .venv/bin/python -m pytest -q tests/e2e/test_smoke.py -m e2e
```

## OTA Gate

Multi-machine OTA verification needs a real two-host link, so public CI does not
run it. A repository operator runs the full suite manually before promoting a
candidate to `main`.

A generic OTA run:

1. stages and installs the current rosotacom source on both hosts,
2. stages the complete active project and any external deployment file,
3. resolves named hosts or raw peer addresses,
4. starts identity `a` on host A and identity `b` on host B,
5. starts synthetic publishers with `rosotacom publish-test-topics` where needed,
6. asserts delivery with `rosotacom test`,
7. asserts local-topic isolation with `rosotacom probe-publish` and
   `rosotacom probe-check --expect absent`,
8. collects each host's `session-instances/` logs and cleans up.

Use `rosotacom ota-smoke TARGET --peer-address ... --peer-ssh ...` for a
configuration-free operator run, or map peers to named hosts with `--peer`
through the active project's deployment file. Add `--interactive` to open a
local control tmux for the same run; each peer gets an attachable
communication/catmux window with a live status pane below it, and scenario
targets also get native application-container windows. Stop it with
`rosotacom ota-smoke TARGET --interactive --stop`.

External runners should use `ota_suite_sessions()` to discover the scenario set
from examples and generated test-configs instead of hardcoding transport names.
